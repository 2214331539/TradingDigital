## 一、产品定位

ChatAI 是一个类 ChatGPT 的 Web 端 AI 对话产品。

第一版的核心目标是完整实现一个稳定、流畅、体验良好的 AI 对话系统。用户可以像使用 ChatGPT 网页版一样，通过网页端完成自然语言对话、内容生成、问题解答、文本润色、代码解释、学习辅导、方案设计等基础 AI 任务。

第一版必须优先复刻以下核心体验：

1. 左侧会话侧边栏、历史会话分组、新建聊天、会话搜索、归档和收藏。
2. 中间对话流、用户消息、AI 消息、Markdown/代码块/表格/数学公式展示。
3. 底部自适应输入框、Enter 发送、Shift + Enter 换行、生成中停止、失败重试。
4. 模型选择器、助手预设、临时聊天、重新生成、编辑问题后重新生成。
5. 深色/浅色主题、响应式布局、桌面端优先并兼顾移动端基础可用。
6. 企业内部权限管理，包括超级管理员、管理员、普通用户三类核心角色。

第一版产品重点包括：

1. 高度贴近 ChatGPT 的 Web 端对话体验。
    
2. 完整的会话管理能力。
    
3. 模型选择与回答控制能力。
    
4. 用户账号与权限管理能力。
    
5. 管理后台与基础运营能力。
    
6. 为第二版知识库/工具系统预留松耦合扩展接口。
    

知识库、企业数据源、API 工具调用、RAG 检索增强、数据库查询等功能，不放在第一版主流程中实现，统一规划到第二版。

## 二、产品核心原则

### 2.1 第一版只做 ChatAI Core

第一版只关注“AI 对话产品本身”。

也就是说，第一版要先把以下体验做好：

- 页面像 ChatGPT。
    
- 对话像 ChatGPT。
    
- 历史记录像 ChatGPT。
    
- 输入框像 ChatGPT。
    
- 消息流式生成像 ChatGPT。
    
- 用户可以管理自己的聊天。
    
- 管理员可以管理用户和权限。
    
- 系统可以接入不同大模型。
    

### 2.2 知识库与 ChatAI 解耦

知识库不内嵌在 ChatAI 系统中。

未来知识库应该作为独立服务存在，例如：

- Knowledge Service
    
- Tool Service
    
- API Service
    
- Data Query Service
    
- RAG Service
    

ChatAI Core 只通过后端接口调用这些外部服务。

第一版只预留接口，不实现知识库管理页面。

### 2.3 先做通用 AI 助手，再做企业增强

产品演进路线应该是：

第一版：类 ChatGPT 通用对话系统。  
第二版：外接知识库与工具调用。  
第三版：企业数据查询与业务助手。  
第四版：多 Agent、工作流、自动化任务。

第一版的成功标准是：即使没有知识库，这个产品本身也应该是一个可用、好用、完整的 AI 对话产品。

## 三、目标用户

### 3.1 普通用户

普通用户是 ChatAI 的主要使用者。
主要功能就是像使用chatgpt一样，完成自然语言输入和模型回答输出的功能。

### 3.2 管理员

管理员负责管理系统中的用户、角色、模型、会话策略和基础系统设置。

典型任务包括：

- 创建用户
    
- 禁用用户
    
- 分配角色
    
- 管理模型访问权限
    
- 查看系统使用情况
    
- 查看基础日志
    
- 配置系统级参数
    

### 3.4 超级管理员

超级管理员是平台最高权限角色。

如果产品未来做成 SaaS，多企业共用一套系统，则超级管理员用于管理多个租户。

如果第一版只是单企业内部部署，也可以暂时不做复杂多租户，只保留超级管理员角色。

# 六、用户端功能模块设计

## 模块一：账号系统

### 1.1 登录

用户可以通过账号密码登录系统。

登录方式包括：

- 邮箱 + 密码

    
- 手机号 + 密码
    

第一版建议优先实现：

- 邮箱 + 密码登录
    

后续可扩展：

- 手机验证码登录
    
- 企业微信登录
    
- 飞书登录
    
- 钉钉登录
    
- GitHub 登录
    
- Google 登录
    
- SSO 单点登录
    

### 1.2 注册

根据产品部署方式决定是否开放注册。

如果是内部系统，建议关闭公开注册，由管理员创建账号。

如果是 SaaS 产品，可以开放注册。
第一版采用管理员创建账号的功能进行登录

注册字段包括：

- 邮箱
    
- 用户名
    
- 密码
    
- 确认密码
    

### 1.3 忘记密码

用户可以通过邮箱找回密码。

流程：

1. 用户输入邮箱。
    
2. 系统发送重置链接。
    
3. 用户点击链接。
    
4. 用户设置新密码。
    
5. 系统提示修改成功。
    

### 1.4 退出登录

用户可以从头像菜单退出登录。

退出后清除当前登录态，跳转到登录页。

### 1.5 登录态保持

系统支持登录态保持。

建议第一版支持：

- Access Token
    
- Refresh Token
    
- Token 自动刷新
    
- 登录过期后重新登录

## 模块二：Chat 主页面

Chat 主页面是整个产品最核心的页面，需要高度复刻 ChatGPT 网页端体验。

### 2.1 页面布局

页面由三部分组成：

1. 左侧会话侧边栏
    
2. 中间对话内容区
    
3. 底部消息输入区
    

### 2.2 左侧会话侧边栏

左侧栏功能包括：

- 新建聊天按钮
    
- 历史会话列表
    
- 会话搜索入口
    
- 项目/分组入口
    
- 收藏入口
    
- 归档入口
    
- 用户头像与设置入口
    

### 2.3 会话列表展示

会话列表按时间分组展示。

建议分组：

- 今天
    
- 昨天
    
- 最近 7 天
    
- 最近 30 天
    
- 更早
    

每个会话展示：

- 会话标题
    
- 最近更新时间
    
- 是否收藏
    
- 更多操作按钮
    

### 2.4 会话更多操作

每个会话支持：

- 重命名
    
- 收藏
    
- 取消收藏
    
- 归档
    
- 删除
    
- 分享
    
- 移动到项目/分组
    

### 2.5 侧边栏收起

用户可以收起左侧栏。

收起后：

- 中间对话区自动变宽。
    
- 顶部保留展开按钮。
    
- 移动端默认收起侧边栏。

## 模块三：新建对话

### 3.1 创建新聊天

用户点击“新建聊天”后，系统创建一个空白会话。

空白会话页面展示：

- 产品名称
    
- 欢迎语
    
- 示例 Prompt 卡片
    
- 底部输入框
    

### 3.2 欢迎语

示例：

> 我能帮你做什么？

或者：

> 有什么可以帮你？

### 3.3 示例 Prompt 卡片

首页可以提供 4 个示例问题。

例如：

1. 帮我写一份项目计划
    
2. 解释一下这段代码
    
3. 帮我优化这段文字
    
4. 给我生成一份学习路线
    

示例卡片点击后，自动填入输入框，用户可以继续编辑。

### 3.4 首轮消息提交

用户输入第一条消息并提交后：

1. 系统创建会话记录。
    
2. 用户消息展示在对话区。
    
3. AI 开始流式生成回答。
    
4. 系统根据第一轮内容自动生成会话标题。

## 模块四：消息输入框

输入框是体验最关键的组件之一。

### 4.1 基础输入

输入框支持多行文本输入。

行为要求：

- 输入框随内容自动增高。
    
- 设置最大高度，超过后内部滚动。
    
- Enter 发送。
    
- Shift + Enter 换行。
    
- 输入为空时，发送按钮禁用。
    

### 4.2 发送按钮

发送按钮位于输入框右侧或右下角。

状态包括：

- 可发送
    
- 不可发送
    
- 生成中变为停止按钮
    

### 4.3 停止生成

AI 回答生成过程中，发送按钮切换为停止按钮。

用户点击后：

1. 前端中断流式接收。
    
2. 后端停止或标记取消生成。
    
3. 已生成内容保留。
    
4. 消息状态标记为“已停止”。
    

### 4.4 继续生成

如果回答被中断，用户可以点击“继续生成”。

系统基于当前上下文继续补全回答。

### 4.5 输入历史

输入框可以支持上下键切换用户近期输入记录。

第一版可作为可选功能。

### 4.6 输入内容持久化

如果用户刷新页面，未发送的输入内容可以保留在本地。

第一版可使用 localStorage 实现。

## 模块六：多轮上下文对话

### 6.1 上下文保持

用户在同一个会话中的连续消息，系统需要按上下文发送给模型。

例如：

用户：

> 帮我写一份产品介绍。

AI 回答后，用户继续问：

> 再写得口语化一点。

系统需要理解“再写得口语化一点”是针对上一轮回答。

### 6.2 上下文长度控制

由于模型上下文有限，系统需要管理历史消息。

策略包括：

- 发送最近 N 轮消息
    
- 超长会话自动摘要
    
- 根据模型上下文长度裁剪
    
- 保留系统提示词和最近消息
    

### 6.3 会话摘要

当会话很长时，系统可以自动生成内部摘要。

摘要不一定展示给用户，但用于保留长期上下文。

第一版可以先实现简单策略：

- 默认发送最近 20 条消息。
    
- 超过限制后只保留最近消息。
    
- 会话摘要放到后续版本。
    

### 6.4 上下文清除

用户可以在当前会话中清除上下文。

清除后：

- 旧消息仍保留在页面。
    
- 后续提问不再携带旧上下文。
    
- 页面提示“上下文已重置”。

## 模块七：回答控制功能

### 7.1 重新生成

用户可以对 AI 回答点击“重新生成”。

重新生成时：

1. 删除或保留旧回答版本。
    
2. 重新请求模型。
    
3. 生成新的回答。
    
4. 用户可以在多个回答版本间切换。
    

### 7.2 回答版本切换

同一个用户问题可能对应多个 AI 回答版本。

页面上可以展示：

- 1 / 2
    
- 2 / 2
    

用户可以左右切换查看不同版本。

### 7.3 编辑问题并重试

用户可以编辑自己已经发送的问题。

编辑后：

1. 当前问题后的所有消息进入分支状态。
    
2. 系统基于新问题重新生成回答。
    
3. 原始对话可被保留为历史版本。
    

第一版可以简化实现：

- 编辑问题后，删除该问题后面的所有消息。
    
- 重新生成新回答。
    

后续版本再做完整分支树。

### 7.4 复制回答

每条 AI 消息支持复制。

复制格式：

- 默认复制纯文本。
    
- 代码块单独复制。
    
- 表格按 Markdown 格式复制。
    

### 7.5 点赞与点踩

每条 AI 消息支持反馈。

反馈类型：

- 点赞
    
- 点踩
    

点踩后可以弹出原因：

- 没有回答我的问题
    
- 回答不准确
    
- 内容太长
    
- 内容太短
    
- 格式不好
    
- 其他
    

### 7.6 分享回答

第一版可以支持分享整个会话，而不是单条回答。

分享功能见后文“共享链接模块”。

## 模块八：会话管理

### 8.1 会话自动命名

系统根据第一轮用户问题自动生成会话标题。

例如：

用户第一句话：

> 帮我写一份电商库存管理系统的产品文档。

自动标题：

> 电商库存管理系统产品文档

### 8.2 会话重命名

用户可以手动修改会话标题。

重命名入口：

- 左侧会话列表更多按钮
    
- 对话顶部标题区域
    

### 8.3 会话搜索

用户可以搜索历史会话。

搜索范围：

- 会话标题
    
- 用户消息
    
- AI 回答内容
    

搜索结果展示：

- 会话标题
    
- 命中的消息片段
    
- 最近更新时间
    

点击搜索结果后跳转到对应会话。

### 8.4 会话删除

用户可以删除会话。

删除前需要二次确认。

提示：

> 删除后该会话将无法恢复，确认删除吗？

### 8.5 批量删除

个人设置中可以提供“清空所有会话”功能。

该操作需要强确认。

### 8.6 会话归档

用户可以将会话归档。

归档效果：

- 从左侧默认列表隐藏。
    
- 不删除数据。
    
- 可以在“归档会话”中找回。
    

### 8.7 取消归档

用户可以将已归档会话恢复到正常会话列表。

### 8.8 会话收藏

用户可以收藏重要会话。

收藏后的会话可在“收藏”列表中查看。

### 8.9 会话排序

默认按最近更新时间倒序排列。

后续可支持：

- 按创建时间排序
    
- 按收藏优先
    
- 按项目分组排序

## 模块九：临时聊天

### 9.1 临时聊天入口

用户可以从顶部模型选择区域或侧边栏进入临时聊天。

临时聊天用于不希望保存历史记录的场景。

### 9.2 临时聊天特征

临时聊天具有以下特点：

- 不出现在历史会话列表。
    
- 刷新或关闭后不可恢复。
    
- 不参与长期记忆。
    
- 不用于自动会话命名。
    
- 页面有明显的临时状态提示。
    

### 9.3 临时聊天提示

进入临时聊天后，页面顶部展示提示：

> 当前为临时聊天，本次对话不会保存到历史记录。

### 9.4 退出临时聊天

用户可以退出临时聊天并返回普通聊天。

如果用户希望保留内容，可以提供“保存为普通会话”按钮。

## 模块十：项目/分组功能

### 10.1 项目定位

项目功能用于管理一组相关会话。

它不是知识库，也不是文件系统，而是会话组织方式。

例如：

- 毕业论文
    
- Shopify 插件开发
    
- 个人博客项目
    
- 期末复习
    
- 电商业务分析
    
- 教案写作
    

### 10.2 创建项目

用户可以创建项目。

项目字段：

- 项目名称
    
- 项目描述
    
- 创建时间
    
- 更新时间
    
- 所属用户
    

### 10.3 项目内会话

用户可以在项目中创建多个会话。

项目内会话默认归属该项目。

### 10.4 移动会话到项目

用户可以把已有会话移动到某个项目。

### 10.5 项目删除

删除项目时，需要确认：

- 仅删除项目，不删除会话
    
- 删除项目及其中会话
    

第一版建议默认仅删除项目，不删除会话。

### 10.6 第二版扩展

第二版中，项目可以进一步绑定：

- 外部知识库
    
- 外部工具
    
- 项目级 Prompt
    
- 项目级上下文
    

但第一版不做这些能力。

# 七、权限管理功能设计

权限管理是第一版除对话功能外的核心能力。

## 7.1 权限模型

第一版采用 RBAC 角色权限模型。

即：

用户 → 角色 → 权限

一个用户可以拥有一个或多个角色。

一个角色可以拥有多个权限。

## 7.2 基础角色

第一版建议设置四类角色：

1. 超级管理员
    
2. 管理员
    
3. 普通用户
    
4. 游客/试用用户
    

如果是企业版，可以增加：

5. 部门管理员
    
6. 高级用户
    

---

## 7.3 超级管理员

超级管理员拥有最高权限。

权限包括：

- 管理所有用户
    
- 管理所有角色
    
- 管理所有模型
    
- 查看系统配置
    
- 修改系统设置
    
- 查看系统日志
    
- 配置平台参数
    
- 启用/禁用功能模块
    

如果未来做 SaaS，超级管理员还负责：

- 创建租户
    
- 禁用租户
    
- 查看租户用量
    
- 配置租户套餐
    

---

## 7.4 管理员

管理员负责日常系统管理。

权限包括：

- 创建用户
    
- 禁用用户
    
- 重置用户密码
    
- 分配普通角色
    
- 查看用户列表
    
- 查看使用统计
    
- 管理模型可见范围
    
- 查看基础操作日志
    

管理员不一定可以查看所有用户的聊天内容。

建议第一版默认策略：

- 管理员可以看到用户使用量。
    
- 管理员不能直接打开用户私人会话内容。
    
- 超级管理员可以通过特殊审计权限查看必要内容。
    

---

## 7.5 普通用户

普通用户是主要使用者。

权限包括：

- 使用 ChatAI 对话
    
- 新建会话
    
- 删除自己的会话
    
- 收藏自己的会话
    
- 归档自己的会话
    
- 搜索自己的会话
    
- 分享自己的会话
    
- 修改个人设置
    
- 导出自己的会话
    

普通用户不能：

- 管理其他用户
    
- 修改模型配置
    
- 查看系统日志
    
- 查看他人会话
    
- 修改角色权限
    

---

## 7.6 游客/试用用户

游客用户用于产品体验。

权限限制：

- 可以发起少量对话
    
- 不保存长期历史
    
- 不能导出数据
    
- 不能创建项目
    
- 不能使用高级模型
    
- 不能分享会话
    

游客适合 SaaS 产品试用场景。

如果是企业内部系统，可以不开放游客角色。

## 7.9 会话隐私策略

会话默认属于创建者本人。

规则：

- 用户只能看到自己的会话。
    
- 用户分享后，其他有权限的人才能查看。
    
- 管理员默认不能查看用户会话正文。
    
- 系统可以记录必要的审计日志。
    
- 高风险审计需要超级管理员权限。
    

这样既满足企业管理需要，也避免普通管理员滥看用户对话。

# 九、核心用户流程

## 9.1 普通对话流程

1. 用户登录系统。
    
2. 进入 Chat 主页面。
    
3. 点击新建聊天。
    
4. 输入问题。
    
5. 点击发送。
    
6. 系统展示用户消息。
    
7. AI 流式生成回答。
    
8. 用户继续追问。
    
9. 系统保持上下文对话。
    
10. 会话自动保存到历史记录。
    

## 9.2 编辑问题流程

1. 用户点击某条用户消息的编辑按钮。
    
2. 输入框切换为编辑状态。
    
3. 用户修改问题。
    
4. 点击保存并重新生成。
    
5. 系统更新该条问题。
    
6. 该问题后的回答重新生成。
    
7. 会话更新时间更新。
    

## 9.3 重新生成流程

1. 用户点击 AI 回答下方的重新生成按钮。
    
2. 系统基于同一个用户问题重新请求模型。
    
3. 生成新的回答版本。
    
4. 用户可以切换查看旧版本和新版本。
    

## 9.4 会话搜索流程

1. 用户点击左侧搜索按钮。
    
2. 弹出搜索框。
    
3. 用户输入关键词。
    
4. 系统搜索会话标题和消息内容。
    
5. 展示命中结果。
    
6. 用户点击结果进入对应会话。
    

## 9.5 临时聊天流程

1. 用户点击临时聊天入口。
    
2. 系统进入临时聊天页面。
    
3. 用户开始对话。
    
4. 系统不保存该会话到历史列表。
    
5. 用户关闭页面后，会话不可恢复。
    
6. 用户也可以手动保存为普通会话。
    

## 9.6 分享会话流程

1. 用户打开某个会话。
    
2. 点击分享按钮。
    
3. 系统生成分享链接。
    
4. 用户复制链接。
    
5. 其他有权限用户访问链接。
    
6. 页面以只读方式展示该会话。
    
7. 用户可以关闭分享链接。
    

## 9.7 管理员创建用户流程

1. 管理员进入后台。
    
2. 打开用户管理页面。
    
3. 点击新增用户。
    
4. 填写邮箱、用户名、角色。
    
5. 系统生成初始密码或发送邀请邮件。
    
6. 用户登录后修改密码。

# 十三、第二版知识库扩展规划

第二版再实现知识库相关能力。

但第二版的设计原则是：知识库系统和 ChatAI Core 松耦合。

## 13.1 松耦合架构

系统拆分为：

1. ChatAI Core  
    负责用户、会话、消息、模型调用、权限、页面交互。
    
2. Knowledge Service  
    负责文档上传、解析、切片、向量化、检索、知识库权限。
    
3. Tool Service  
    负责 API 工具注册、参数抽取、工具调用、调用日志。
    
4. Data Service  
    负责数据库连接、查询执行、数据权限、结果格式化。
    

ChatAI Core 不直接处理知识库细节。

它只通过统一接口请求外部服务。

## 13.2 ChatAI 与知识库通信方式

未来可以通过以下方式通信：

```text
用户问题
  ↓
ChatAI Core
  ↓
判断是否需要外部知识/工具
  ↓
调用 Knowledge Service / Tool Service
  ↓
获得检索结果或工具结果
  ↓
组合上下文
  ↓
调用大模型
  ↓
返回最终回答
```

## 13.3 第一版预留接口

第一版只需要预留以下抽象：

- ExternalContextProvider
    
- ToolProvider
    
- KnowledgeProvider
    
- AssistantCapability
    
- ConversationContextBuilder
    

但不实现具体知识库逻辑。

这样第二版扩展时，不需要重构 ChatAI Core。

## 13.4 第二版新增功能

第二版新增：

- 知识库管理
    
- 文档上传
    
- 文档解析
    
- 向量检索
    
- 引用来源

- 参数追问
    
- 企业数据查询
    
- 知识库权限
    
- 工具调用日志

# 十四、产品验收标准

## 14.1 对话体验验收

合格标准：

- 新建会话流程顺畅。
    
- 用户发送消息后，AI 可以流式输出。
    
- 输出过程中可以停止。
    
- 回答支持 Markdown。
    
- 代码块可以复制。
    
- 多轮上下文可正常工作。
    
- 重新生成可用。
    
- 编辑问题可用。
    
- 页面刷新后历史会话仍然存在。
    

## 14.2 会话管理验收

合格标准：

- 会话自动保存。
    
- 会话自动命名。
    
- 会话可以重命名。
    
- 会话可以删除。
    
- 会话可以搜索。
    
- 会话可以归档。
    
- 会话可以收藏。
    
- 用户只能看到自己的会话。
    

## 14.3 权限验收

合格标准：

- 未登录用户不能访问 Chat 页面。
    
- 普通用户不能访问管理后台。
    
- 管理员可以管理用户。
    
- 普通用户不能管理模型。
    
- 不同角色可用模型不同。
    
- 用户不能查看他人私人会话。
    
- 所有关键操作有日志。
    

## 14.4 模型管理验收

合格标准：

- 管理员可以新增模型。
    
- 管理员可以禁用模型。
    
- 用户只能看到自己有权限的模型。
    
- 模型调用失败时有错误提示。
    
- 模型调用日志记录完整。
    

## 14.5 UI 体验验收

合格标准：

- 页面整体接近 ChatGPT Web 端体验。
    
- 左侧会话栏清晰。
    
- 中间对话区简洁。
    
- 输入框交互自然。
    
- 生成状态明确。
    
- 深色模式可用。
    
- 移动端基础可用。
