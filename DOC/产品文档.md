# TradeDigital 产品文档

## 1. 产品定位

TradeDigital（电商数字化）是面向企业内部的数字化平台。第一版把原类 ChatGPT 对话系统纳入平台，并统一命名为 `llm` 模块，形成“平台底座 + 业务应用”的结构。

```text
TradeDigital 是总平台
llm 是 TradeDigital 的模型对话模块
KnowledgeBase 是知识库与工具接入模块
后续订单分析、库存分析、采购进度、ERP API 检索等都作为新模块接入
```

## 2. 用户角色

第一版只保留两个业务角色：

| 角色 | 定位 |
|---|---|
| enterprise_admin | 企业管理员，拥有平台管理、IAM、知识库、审计和模型管理权限 |
| employee | 企业员工，只能使用 `llm` 和被授权的知识库查询 |

开发环境 Keycloak 账号：

| 角色 | 邮箱 | 密码 |
|---|---|---|
| 企业管理员 | admin@tradedigital.local | Admin@123456 |
| 员工 | employee@tradedigital.local | Employee@123456 |

## 3. 产品模块

### 3.1 Platform

负责企业级公共能力：

- 企业与组织。
- SSO 登录。
- 用户同步。
- 角色与权限。
- 服务端 Session。
- 审计日志。

### 3.2 llm

负责模型对话体验：

- New chat。
- Search chats。
- Pinned conversations。
- Chats 会话列表。
- ChatGPT 风格消息流。
- 底部输入器。
- SSE 流式输出。
- Markdown、代码块、表格、数学公式渲染。
- 模型选择。
- 助手预设。
- 会话归档、置顶、删除。

llm 不直接决定用户身份，也不直接读取 IAM 用户表。业务接口只依赖平台层注入的 `AuthContext`。

### 3.3 KnowledgeBase

负责知识库和企业工具接入：

- 知识库列表。
- 知识库权限授权。
- 查询入口。
- 企业工具执行入口。

llm 需要知识库结果时，只能调用：

```text
KnowledgeGateway.query()
KnowledgeGateway.list_accessible_knowledge_bases()
KnowledgeGateway.execute_tool()
```

## 4. 第一版不做

- 不拆微服务。
- 不为 llm 单独建数据库。
- 不让业务模块直接共享业务表。
- 不让前端保存 OIDC token、session token 或 client secret。
- 不允许前端权限隐藏代替后端权限判断。
- 管理员第一版不查看员工会话正文，只看用户、角色、审计和统计入口。
