# ChatAI 权限管理设计

## 1. 权限目标

第一版权限管理需要同时满足两个目标：

1. 普通用户可以像使用 ChatGPT 一样管理自己的对话和设置。
2. 企业管理员可以管理账号、角色、模型、系统配置和日志，但不能默认查看用户私人会话正文。

## 2. 权限模型

第一版采用 RBAC：

```text
用户 User
  -> 用户角色 UserRole
    -> 角色 Role
      -> 角色权限 RolePermission
        -> 权限 Permission
```

资源访问采用 RBAC + 所有权校验：

- RBAC 判断用户是否有操作类型权限。
- 所有权校验判断用户是否能访问具体资源。

示例：

- `chat:read_own` 只表示用户有读取自己会话的能力。
- 后端仍需校验 `conversation.user_id == current_user.id`。

## 3. 内置角色

### 3.1 超级管理员 super_admin

定位：系统最高权限。

能力：

- 管理所有用户。
- 管理所有管理员。
- 管理角色和权限。
- 管理模型配置。
- 管理系统设置。
- 查看所有后台统计。
- 查看所有日志。
- 在审计场景下查看会话敏感数据。

限制：

- 查看用户会话正文必须记录审计日志。
- 不建议日常使用超级管理员账号进行普通对话。

### 3.2 管理员 admin

定位：企业内部系统管理员。

能力：

- 创建普通用户。
- 禁用普通用户。
- 重置普通用户密码。
- 给普通用户分配角色。
- 查看用户列表和使用量。
- 管理模型可见范围。
- 查看基础统计和日志。

限制：

- 不能删除或禁用超级管理员。
- 不能给自己提升为超级管理员。
- 不能修改超级管理员权限。
- 默认不能查看用户会话正文。
- 默认不能导出用户私人会话。

### 3.3 普通用户 user

定位：ChatAI 主要使用者。

能力：

- 使用 AI 对话。
- 新建、查看、更新、删除自己的会话。
- 搜索自己的会话。
- 归档、收藏自己的会话。
- 分享自己的会话，受系统策略控制。
- 导出自己的会话，受系统策略控制。
- 修改个人设置。

限制：

- 不能访问管理后台。
- 不能管理用户。
- 不能管理模型。
- 不能查看其他用户会话。
- 不能查看系统日志。

## 5. 模型可见范围

模型访问同时受两个条件控制：

1. 用户角色拥有对应模型使用权限，例如 `model:use_basic`。
2. 模型绑定的允许角色包含当前用户角色。

判断逻辑：

```text
用户角色权限允许使用模型类型
AND
模型 allowed_roles 包含用户任一角色
AND
模型 enabled = true
```

示例：

|模型|允许角色|
|---|---|
|Fast Chat|普通用户、管理员、超级管理员|
|Deep Think|管理员、超级管理员|
|Code Expert|普通用户、管理员、超级管理员，可配置|
|Internal Test Model|超级管理员|

## 6. 数据访问规则

### 6.1 会话数据

普通用户：

- 只能读取自己的会话。
- 只能删除自己的会话。
- 只能导出自己的会话。

管理员：

- 可以查看用户使用量和统计。
- 默认不能打开用户会话正文。
- 可以按策略处理违规账号，但不直接读取内容。

超级管理员：

- 可使用 `chat:audit_all` 审计会话。
- 每次审计必须记录 `operation_logs`。

### 6.2 用户数据

管理员可管理普通用户。

管理员不可：

- 禁用超级管理员。
- 删除超级管理员。
- 修改超级管理员角色。
- 给自己授予更高权限。

超级管理员可管理所有用户。

### 6.3 系统配置

系统设置修改要求：

- 普通用户无权访问。
- 管理员可查看部分配置。
- 超级管理员可修改核心配置。
- 修改必须写操作日志。

## 7. 后端鉴权实现建议

### 7.1 权限依赖

FastAPI 中可以设计依赖：

```python
require_permission("user:create")
require_any_permission(["model:create", "model:update"])
```

### 7.2 资源归属校验

示例：

```python
conversation = get_conversation(conversation_id)
if conversation.user_id != current_user.id:
    raise ForbiddenError()
```

对于超级管理员审计：

```python
if has_permission(current_user, "chat:audit_all"):
    write_audit_log(...)
else:
    raise ForbiddenError()
```

### 7.3 前端权限使用

前端登录后保存：

- 用户 ID。
- 角色列表。
- 权限码列表。

用途：

- 隐藏无权限菜单。
- 隐藏管理后台入口。
- 控制按钮展示。
- 控制路由访问。

注意：前端权限只做体验控制，不能替代后端校验。

## 8. 操作日志要求

必须记录日志的操作：

- 登录成功和失败。
- 创建用户。
- 禁用用户。
- 重置密码。
- 修改角色。
- 修改权限。
- 新增或禁用模型。
- 修改系统设置。
- 删除会话。
- 导出数据。
- 创建或关闭分享链接。
- 超级管理员审计查看会话内容。

日志字段：

- 操作人。
- 操作类型。
- 操作对象。
- 操作时间。
- IP。
- User Agent。
- 操作结果。
- 失败原因。

## 9. 第一版权限验收

- 未登录用户不能访问 Chat 页面。
- 普通用户不能访问 `/admin`。
- 普通用户不能调用管理端 API。
- 普通用户不能读取其他用户会话。
- 管理员能创建、禁用、重置普通用户。
- 管理员不能创建超级管理员。
- 管理员默认不能读取用户会话正文。
- 超级管理员可以配置角色权限。
- 不同角色看到的模型列表不同。
- 关键操作写入日志。
