# ChatAI 数据库表设计

## 1. 设计约定

数据库建议使用 PostgreSQL。

通用约定：

- 主键统一使用 UUID。
- 时间字段统一使用 `timestamptz`。
- 软删除字段使用 `deleted_at`。
- 状态字段使用短字符串枚举。
- 业务表默认包含 `created_at`、`updated_at`。
- 企业扩展预留 `organization_id`，第一版可创建一个默认组织。
- 大文本字段使用 `text`。
- 配置类 JSON 使用 `jsonb`。

## 2. 枚举定义

|值|说明|
|---|---|
|`active`|正常|
|`disabled`|已禁用|
|`pending`|待激活|
|`deleted`|已删除|

### 2.2 消息角色

|值|说明|
|---|---|
|`system`|系统提示|
|`user`|用户消息|
|`assistant`|AI 消息|
|`tool`|工具消息，第一版预留|

### 2.3 消息状态

|值|说明|
|---|---|
|`pending`|待生成|
|`streaming`|生成中|
|`completed`|完成|
|`stopped`|用户停止|
|`failed`|失败|
|`deleted`|已删除|

### 2.4 会话状态

|值|说明|
|---|---|
|`active`|正常|
|`archived`|已归档|
|`deleted`|已删除|

## 3. 组织表 organizations

第一版单企业部署时可以只初始化一个默认组织。未来 SaaS 多租户时可扩展。

|字段|类型|约束|说明|
|---|---|---|---|
|`id`|uuid|PK|组织 ID|
|`name`|varchar(100)|not null|组织名称|
|`code`|varchar(64)|unique|组织编码|
|`status`|varchar(32)|not null|状态|
|`created_at`|timestamptz|not null|创建时间|
|`updated_at`|timestamptz|not null|更新时间|

索引：

- `idx_organizations_status(status)`

## 11. 数据隔离规则

- 用户查询会话必须限制 `conversations.user_id = current_user.id`。
- 消息查询必须通过会话归属校验。
- 管理员默认不能查询用户会话正文。
- 超级管理员使用审计权限查看敏感数据时必须记录操作日志。
- 模型列表按用户角色过滤。
- 删除默认软删除，保留审计能力。
